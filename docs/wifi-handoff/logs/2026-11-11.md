### 代码级根因（不是猜，逐层可复现）
`wifi-wcn3990/source/PicassoWlan.cpp`：
- `#undef IOSleep` + `#define IOSleep(ms) picasso_sleep_ms(ms)`；
  `picasso_sleep_ms()` 调 `machine_delay_until()` = XNU **纯忙等自旋分支**
  （`osfmk/kern/clock.c` 中只有 `ml_delay_should_spin()` 为真 /
  抢占关闭 / 中断关闭时才走它；让出 CPU 的路径是
  `clock_delay_until -> assert_wait_deadline + thread_block`）。
- 两个**无限循环**用它：
  * `modem_thread` GLINK watch：`glink_ms` 默认 **0** →
    `for (ms=0; glink_ms==0 || ms<glink_ms; ms++)` 永不退出，
    每轮 `glink_poll` + `picasso_wlan_ce_poll` + `picasso_usb_console_drive_poll`
    + `IOSleep(1)` 忙等；
  * `modem_monitor`：`for(;;) IOSleep(500)` 忙等。
  两个各钉一个大核 → 正好对应 d1/d2 busy=100；
  再加 `hakios.net.c net_thread` 每 2ms 一条 `link->poll` 也调同一个 HIF poll。
- 官方 XNU/Apple 文档实证：`IOSleep(ms)=delay_for_interval(ms,kMillisecondScale)`
  **阻塞调用线程、给其他进程时间**；`IODelay` 才是纯自旋。
  `HakiosCompat.cpp` 用原生 `IOSleep(150000)` 做延迟，本板 HIF 准时 168s 启动
  且这 150s 内 UI 有反应 ⇒ 原生 IOSleep 在本板确定会让出 CPU。
