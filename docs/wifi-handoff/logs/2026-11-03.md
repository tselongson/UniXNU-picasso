## 根因定位:电池驱动 SpmI.cpp 裸用物理地址
- SpmI.cpp 的 spmiInit 只做 `arbiter = (uint8_t*)0x0c440000` 指针赋值,**从未 IOKit 映射**;
  PmicService::start → tick → 第一次 spmiRead 写 0x0c440010(未映射虚拟地址)→ 内核缺页 →
  启动监视器停在诊断页(PC=0, IRQ 关)。这就是 v266/v268/v269 卡死的根因。
- 对照:按键探针用 IODeviceMemory::withRange + map(kIOMapAnywhere|kIOMapInhibitCache) 正确映射,
  旧版能读 SPMI 寄存器,所以按键无罪。v265 没有电池驱动所以是活的。
- 第二个 bug:SpmI 用 core 窗口的 CMD 0x10/STATUS 0x08,但这块是 v5 布局——命令/状态在
  per-APID channel 窗口(chnls + 0x10000*apid: cmd 0x00 status 0x08 wdata 0x10 rdata 0x18)。
- 修复计划:重启用电池前,照 ButtonProbe 模式映射两个窗口 + 换 channel 窗口布局 + 先读 REVID
  验证通路。修复前电池探针保持关闭(native-pmic 参数不传)。

## 重要修正:卡死是两个独立 bug,每版各踩一个
